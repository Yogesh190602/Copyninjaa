## Project Overview

CopyNinja is a clipboard history manager for Linux (Wayland & X11) written in Rust. It has two modes: a background **daemon** (`copyninja daemon`) that monitors the clipboard, and a **picker** (`copyninja pick`) that shows a GTK4 UI for selecting past entries. It supports text and images, cross-device sync, and auto-paste.

## Build & Development Commands

```bash
cargo build --release     # Build release binary
cargo test                # Run all unit tests
cargo clippy              # Lint
cargo fmt                 # Format
cargo test <test_name>    # Run a single test by name
./install.sh              # Build + install binary + systemd service + keybinding
./uninstall.sh            # Remove everything
```

Runtime dependencies: `gtk4`, `wl-clipboard`, `wtype`, `xclip`, `xdotool`, `ydotool`, `libnotify`. Building needs Rust 1.89+ (`File::lock`).

## Architecture

Two-process model invoked via clap subcommands in `main.rs`:

- **Daemon** (`src/daemon/`): Runs a tokio async runtime. Detects session type (Wayland/X11) in `session.rs`, then starts the appropriate clipboard watcher — `wayland.rs` uses `wl-paste --watch` (event-driven), `x11.rs` uses `xclip` (polling). Exposes a D-Bus interface (`dbus.rs`) for programmatic entry addition. Has a retry loop (up to 5 min) for session availability at boot. If native Wayland fails, falls back to X11/XWayland.

- **Picker** (`src/picker/`): GTK4 application. `app.rs` builds the UI (stylesheet generated by `css.rs` from the resolved theme, then the user's `~/.config/copyninja/style.css` at USER priority), handles search/keybindings/cached image thumbnails (`<image_dir>/thumbs/`); keys are handled in the capture phase so focus stays in the search field. `preview.rs` holds the pure text helpers (previews, search highlighting, labels). `paste.rs` implements the auto-paste fallback chain: ydotool key (GNOME first) → wtype → xdotool (X11 or XWayland targets only) → ydotool key → ydotool type (single-line ASCII, never terminals) → copy-only.

- **Storage** (`src/storage.rs`): Global singleton via `OnceLock<Storage>`. Manages JSON history file with backup rotation, MD5-based deduplication, and entry pruning. Handles backward compatibility with legacy text-only entries via `ClipEntry::resolved_content()`.

- **Theme** (`src/theme.rs`): Built-in palettes (`PRESETS`, 11 colors each, in `Palette` field order), `resolve()` for the `[appearance]` config (handles `auto` and color overrides), and color parsing. No GTK dependency, so config validation can use it.

- **Content** (`src/content.rs`): `ClipContent` enum — `Text { text, preview }` or `Image { path, mime }`. Uses serde tagged enum (`#[serde(tag = "type")]`).

- **Config** (`src/config.rs`): TOML config from `~/.config/copyninja/config.toml`. All fields optional with defaults via `#[serde(default)]`. Includes `SyncConfig` sub-table.

- **Sync** (`src/sync.rs`): File-based cross-device sync. `Storage` publishes each change (copy, pin, delete, clear) to the sync folder as it happens; the daemon's watcher thread imports entries, images and timestamped tombstones from other devices (newest change wins), prunes to `max_entries`, and trims the shared folder.

## Key Design Decisions

- Storage is a global singleton (`OnceLock`) initialized in `main.rs` after CLI parsing
- Every history change goes through `Storage::update`/`update_if`, which holds an exclusive file lock (`<history>.lock`) for the read-modify-write, so the daemon, picker and sync thread can't lose each other's changes. Files are written atomically with mode 0600
- Image paths stored in entries are never trusted for deletion; only files directly inside `image_dir` are removed
- Sync treats the shared folder as untrusted: hashes are validated (12 lowercase hex) before use in paths, and image paths are rebuilt locally
- Legacy JSON format support: `ClipEntry` has both `content: Option<ClipContent>` and old `text`/`preview` fields (still read, no longer written)
- Config is read at startup: the picker re-reads it on every launch, the daemon needs a restart. Bad keys are skipped individually and reported as warnings once the logger is up
- RUST_LOG env var overrides the config `log_level`
